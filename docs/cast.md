# Cast Islands v2 (v1.0.31, current)

**The post-render narrative reconciler was removed.** Cast now reserves exact locations upstream, then paints the saved wardrobe inside those locations. This is **not** Lumiverse's automatic styled-HTML-island extractor; it uses the supported backend display-only `render` content processor to produce valid, inert `<span>` placeholders and then attaches a Cast-owned Shadow Root when the host renders them.

The saved source keeps `<swarm-cast=Shoto-neutral><font color="#599CE3">"Hello."</font></swarm-cast>`. The `render` projection substitutes a sanitized HTML placeholder **in place**. Only the closed packet is replaced. Outside prose, Markdown, font colors of other speakers, and every foreign widget's payload are not touched. Partial in-flight packets remain hidden until closed; completed packets can mount before generation ends.

Each slot carries a base64url-encoded normalized dialogue body (not arbitrary executable HTML), its key, and a readable plain-text fallback. Hydration uses the existing `renderCastTags` safe renderer, lazy-loaded member images, and Shadow DOM styling. The frontend never reconstructs deleted narration, moves a slot, or modifies an original text node. If a layout cannot hydrate, the authored speech remains readable instead of disappearing.

For old-host compatibility the registration feature-detects `spindle.registerMessageContentProcessor`. If it is unavailable, **no unsafe post-render fallback runs**; upgrade Lumiverse to use the current display-preprocess API. Re-open or rerender messages after enabling the extension to obtain the new display projection.

Validation: `node tests/cast-island-pipeline-contract.mjs`, `python tests/cast-island-api-browser.py`, `node tests/cast-contract.mjs`, `node tests/cast-envelope-contract.mjs`, and `npm run build`. Browser coverage uses a minimally viable Lumiverse-like message-root/stream mock with real compiled frontend code. Test actual Lumiverse with a long multi-expression reply, a swipe, and an unrelated branch widget before treating this as production-proven.

# Cast album

Cast sits beside Generate and Styles. The album has a compact header, searchable cast covers, per-chat activation, and a member workspace. Members live in an independent library; neither creating one nor opening Expressions requires a character card, bound folder, or generation connection.

## Create and use a cast

1. Create a cast, choose an album color, and add members from the button beneath the roster or the first-member starting screen. A member can be a cast character or your persona. Start from scratch, or choose **From Lumiverse character** to copy the character’s mapped expressions or one of its native expression groups. Character search and paging use the host’s character summary API. Imported mappings are an independent snapshot in Cast; editing Cast does not change the original character.
2. Save their name, expression prefix, appearance notes, and optional reference image. References use the shared Output Library picker, with folder search, image search, pagination, and PNG/JPEG/WebP uploads up to 50 MB. Closing it restores the underlying library’s visibility and previous folder/selection. Uploads use Lumiverse's authenticated image API.
3. Open Expressions. The native generation, enhancement, background-removal, saved-image picker, progress, cancellation and retry workflow is retained. Cast opens the same full-screen V6 Expression Studio used by output folders, with its portrait gallery, contained inline direction editor, inspector, reusable bank, aspect controls and four stages. The album shows every saved expression and presentation preferences; editing remains in the shared modal. The final stage is **Save to cast member** in Cast and **Send to Lumiverse** in a character folder. Cast’s modal does not open the Output Library underneath on close. Opening and choosing saved images works without a generation connection; rendering and finishing require a SwarmUI connection selected in Generate.
4. Rendered Cast images go into an automatically created **unlinked** output folder for that member (`cast:<member id>`). Choose **Generation identity** in Identity or when creating a member: an unbound member uses its own appearance notes, while a saved character folder supplies its visual recipe/look. Appearance notes can override the chosen folder’s base appearance. A selected member reference is retained in Cast; linking an identity does not publish expressions back to that card.
5. Use **In this chat** or **Use cast… → In the narrative** to activate a cast. Browsing/opening an album does not activate it. Each chat has its own selection and the prompt toggle belongs to the cast. Existing version-1 account-wide activation is preserved as a migration fallback until a chat gets an explicit selection.

Library data is saved to account-scoped extension storage (`cast-library.json`, schema version 2). Image bytes stay in Lumiverse's image library. This is not offline browser storage. Failed saves leave the edits available for retry, and failed creation retries do not duplicate members or casts.

## Expressions and presentation

The member workspace separates Expressions, Identity and Presentation. **Story card** is the default presentation for new casts; **Sticker** and **Portrait** remain available unchanged for existing members. The Presentation tab now opens a **composition-organized picker modal**, with 34 additional named layouts: 3 approved Atelier references (Manga · Chapter Tab, Moonlit Halo and Polaroid · Side Note), 9 sourced from The Basics Run, and 22 sourced from the Saved Layouts Vault. Including the original three, this provides **37 presentation choices** grouped by seven composition families: transparent standees, figure/dialogue overlaps, face crops, photographs/physical tags, graphic panels, cinematic strips, and editorial splits. Each choice shows a live thumbnail using the member’s saved art when one exists. Members can choose an override, set a cast default or reset to inheritance. Legacy `card` and `inline` choices still migrate to Story card and Sticker; existing Portrait choices remain Portrait. The model now emits a **bounded packet** such as `<swarm-cast=Prefix-emotion>"Dialogue."</swarm-cast>`, optionally with `<font color="#599CE3">` around the dialogue. The selected presentation does not change this syntax.

The **default expression** is separate from the **default presentation**. A prefix-only packet such as `<swarm-cast=Mina>"Hello."</swarm-cast>` uses the saved fallback image. An explicit packet such as `<swarm-cast=Mina-joy>"Hello."</swarm-cast>` uses that expression.

Assistant messages resolve complete bounded Cast tags as soon as their own closing delimiter arrives, including during token streaming, manually edited replies and older closed replies. An unfinished trailing Cast packet remains hidden until complete. Story card and Sticker can move immediately adjacent quoted dialogue alongside the image once. The renderer normalizes surrounding quotes and emits a span rather than a browser-quoted `q` element, avoiding doubled quotation marks. Portrait is a separate centered block with the image above its adjacent quoted dialogue. It inherits the surrounding font and the host’s `--lumiverse-prose-dialogue` color. It does not stretch the narrative’s line height. Unknown tags and code examples are left unchanged. The Studio preview uses a smaller string renderer; the live chat uses DOM reconciliation. New packets use **the entire content between `<swarm-cast=...>` and `</swarm-cast>` as the dialogue**. Nothing before or after is eligible for pairing, even if it is quoted. For example:

```html
He checked the street.
<swarm-cast=Shoto-neutral><font color="#599CE3">"He's allowed to take pictures here."</font></swarm-cast>
Katsuki frowned. "That's ridiculous."
```

The closing tag belongs to the source packet and is removed from visible prose along with the opening delimiter. Color comes from the authored font element when present, while the character and their expression determine the image. The live renderer derives the bounded quote from saved source when Lumiverse sanitizes the tags away. Both renderers require complete closing tags. Opening-only legacy packets intentionally remain literal; Studio’s model prompt and copy UI generate only the bounded form. U+2800 braille spaces are normalized in an in-memory parsing copy before matching `<font color>`. Inline code and fenced examples remain literal.

Tags remain the stored message source. Presentation and crop changes update mounted expressions immediately, including earlier replies; they do not write message history on every token. The extension uses public message DOM enumeration and `STREAM_TOKEN_RECEIVED` generation-scoped deltas (token, sequence and generation ID) to bind the real provisional assistant bubble; the saved message API may remain stale for the entire stream. A host can expose the Cast opener as escaped text or as a Chromium-created unknown element, and the binder recognizes both. Scoped observers preserve host text-node identities, handle dialogue split across styled nodes, and restore native content on chat switches and unload. Public REST/message APIs provide older-host role/source reads; user messages and code blocks are excluded. Stable per-occurrence slots retain their image element across host HTML commits. A public `message_body_after` mount hook covers the delayed final/virtualized bubble, and the saved source locates expressions after the final sanitizer removes unknown tag text. If the native quotation also disappears, the live renderer recovers safe caption text and authored font color from the stored assistant packet; when the host cannot supply an anchor, it can still mount a source-backed portrait into the message even if the host left zero-width sentinels or unrelated text. The last usable packet survives transient sanitized API projections but is invalidated on message edits and swipes. HTML-escaped tags in intermediate source projections are also recognized. Surviving narration before or after a missing quotation provides a safer anchor in longer replies. When repeated prose offers many identical anchors, placement uses the saved packet's relative position to select the closest corresponding paragraph. Standalone Cast packets mount between intact narrative blocks instead of moving their original text. While a Lumiverse response editor is open, Cast decoration is suspended, including editors placed beside an inner message body; canceling or saving restores the appropriate presentation without changing the edit textarea. Streaming and final bubbles share the same renderer. Completed closed packets mount progressively, while unfinished source fragments stay hidden; source-backed narration recovery restores long prose a sanitizer already removed without altering surviving native text. The mutation observer follows the current final bubble instead of retaining a detached streaming element. Scrolling only discovers virtualized messages once per animation frame; it does not fetch roles or repaint stable expressions, and toolbar hover/style changes do not invalidate mounted portraits. Explicit native dialogue paint and inline emphasis are retained; if the host strips an authored `<font color>` wrapper, its source color is recovered rather than overridden by a generic inherited host color. Host classes that depend on parent structure, visibility or animation are not transferred. Before consuming the native line, the renderer verifies that every replacement text run has a painted box and matching text; a hidden replacement leaves the original dialogue available. During streaming, it also requires that visible native dialogue belong to the actual Cast unknown-element owner, immediately follow an intact opener, or be uniquely confirmed by sufficient saved prose on both sides. Otherwise Cast defers its caption instead of displaying a duplicate or deleting an unrelated quotation. Cached captions are also checked against the actual DOM so externally cleared contents are repaired. Braille whitespace is normalized for matching only; it is not rewritten in stored messages.

Earlier Studio-generated presentation spans are recovered to their original tags when the library loads or a swipe changes. Recovery recognizes only the generated span/image shape in assistant messages, checks the current source before writing, and patches only the active swipe; unrelated HTML, code, user messages, image assets, and other swipes remain intact.

**Shared crop** stores one non-destructive framing per member. Position and zoom apply to the cropped artwork windows used by named cards, photo/tag formats and compact portraits, while the transparent Moonlit standee and original full Portrait keep the source silhouette intact. Preset markup and scoped CSS are authored in `src/state/cast-presentations.ts`; the original Doctype #3/#5 references and both contributed HTML source catalogs live in `docs/cast-layout-sources/`. `scripts/build-cast-presets.py` can regenerate the catalog when the source designs change (optional authoring dependencies: Python BeautifulSoup and tinycss2). The renderer never persists generated HTML to chat messages. All named looks have exactly one owned image and one native dialogue slot, preserving R4’s stable-scroll, editor, swipe and sanitization protections.

## Optional destinations

**Use cast… → Character card** sends prefixed mappings to the current chat's character or a known character folder. Native cast groups are an additional format; labels are added without replacing other groups. **New asset folder · no card link** copies references to a standalone Lumiverse output folder, retaining the originals. Partial host exports are retryable; successful writes are retained.

**Use cast… → Persona** assigns a selected member's mappings to the active persona under `metadata.swarm_studio_cast`, preserving unrelated metadata. Cast narrative tags use these images. Native persona avatar switching is not exposed by the inspected host API and is not implemented.

Removing a cast/member does not delete image-library assets or previously deployed mappings. Renaming a prefix does not remove earlier deployed keys. Cast assets can be reused across duplicated casts.

### Cast Wardrobe crop workshop (v1.0.18)

Open Cast → Member → Presentation → **Choose a presentation**. The top panel is a Studio-themed crop workshop. Enabling crop allows horizontal/vertical focal placement, zoom and drag-to-position on the member's saved expression. Crop values apply to the member's crop-aware presets and persist with the Cast library, not with the chat message. Turning crop off keeps the chosen preset and restores its unzoomed framing. Approved full transparent portraits are intentionally not forcibly cropped.

The presentation picker uses Studio's palette variables (`--ss-canvas-bg`, `--ss-panel-bg`, `--ss-text`, `--ss-outline`, `--ss-accent`), not fixed dark surfaces. Source-backed geometry fixes are in `scripts/build-cast-presets.py` and its generated `src/state/cast-presentations.ts`. Run the generator before compiling. The Cast reconciliation/mutation pipeline was not changed in this iteration.

### Dialogue color continuity (alpha.11.1)

Color belongs to the speaker, not the card. Keep the same established speaker color in all spoken segments (including speakers without expressions), follow explicit user color instructions, and leave narration uncolored. Example:

```html
<swarm-cast=Shoto-neutral><font color="#599CE3">"No,"</font></swarm-cast> he said quietly. <font color="#599CE3">"I was waiting for you."</font>
```

The ordinary continuation is still native host prose; it does not create another Cast card. The prompt guidance also applies to an empty album with Genesis enabled. No automatic recoloring or historical message rewriting is performed.

### Cast bounded packets (v1.0.21)

The source grammar is `<swarm-cast=member-expression>[optional <font color="#RRGGBB">]"dialogue"[</font>]</swarm-cast>`. Each packet must be closed, and adjacent packets are parsed independently. Do not put narration, other speakers, or raw layout markup inside. Quote and color are source-owned; framed designs and Shadow DOM do not edit the stored message. Legacy opening-only packets are no longer parsed; only completely closed envelopes render. `python tests/cast-r24-progressive-browser.py` exercises braille-colored envelopes, real browser unknown-tag sanitization, adjacent packets separated by narration, progressive streaming, stale same-ID source protection and zero scroll rewrites.

### Shared crop focal positioning (v1.0.22)

A saved member crop overrides a preset's original `object-position` while that member's **Enable shared crop** toggle is on. Zoom is clipped to the preset's own image bay so it cannot spill into captions or neighboring narration. This is handled in the canonical generated presentation CSS, not by modifying the narration DOM or forcing all standees to be cropped. The right-click Looks/Crop and Studio workshop edit the same saved X/Y/zoom values. `python tests/cast-crop-focal-browser.py` verifies the mounted crop at both Y extremes.
