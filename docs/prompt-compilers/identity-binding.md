# Identity ownership

`character="active"` and `persona="active"` are availability flags, not positions. A scene plan's `[character]`, `[persona]` and `[other]` heading markers select ownership independently of subject order. If an owner is marked twice, automatic injection for that owner is disabled. If a marker has no eligible identity source, no saved tags are added. An unseen viewer contributes no visual identity. A multi-NPC card must use `[other]` for independently described NPCs rather than assign its combined saved tag block to a random NPC; keep automatic character printing disabled for those cards.

For compatibility, a single unmarked subject with only the active character enabled can still receive the saved character tags. A raw legacy character-only prompt also retains its existing optional automatic character injection. Raw inline prompts no longer receive implicit persona tags even when persona is enabled. Explicit raw `{{persona_base}}` expansion remains supported with `persona="active"`; the Pocket bridge also preserves explicit persona-only portrait intent. In structured plans, macros expand only in the matching uniquely owned subject; unrelated global fields cannot inject saved identities. A manually authored literal persona description is not removed. The system cannot infer with certainty whether a poorly marked scene actually depicts the persona: the LLM still owns visual intent.

Saved outfit and trigger fragments follow the character owner in a structured plan. Global style retains existing recipe semantics. Since alpha.3, only explicitly selected eligible visual lore contributes, with positive fragments attached to their valid scene field. Negative recipes, reference images and LoRA stacks remain image-wide and can still cause spillover; true regional adapter/LoRA ownership is not solved by string binding. See [visual lore](visual-lore.md).

Raw/compiled diagnostics make it possible to distinguish a mistaken scene plan from incorrect compilation. No chat text, character base tags, persona presets or Cast references are rewritten by the compiler.
