# MOSS-Image: caption, Swarm BBox and native JSON (alpha.6)

## Choose the transport

| Compiler | Provider-bound prompt | Intended use |
| --- | --- | --- |
| MOSS · Caption (`moss`) | Descriptive prose | Ordinary scenes; Auto selects this safe default. |
| MOSS · Swarm BBox (`moss-bbox`) | Prose and `<bbox[x1,y1,x2,y2]:caption>` | Object placement with native Swarm preset expansion. |
| MOSS · Native JSON (`moss-layout`) | Complete JSON layout document | Object boxes and dedicated exact-text items without prompt-mutating presets. |

These are explicit modes for structured inline and Pocket requests. Main Generate remains the direct manual prompt surface; selecting a compiler does not transform arbitrary manual prompts into JSON. Manual Lore and Cast backgrounds retain their caption-oriented behavior. Both layout modes inherit MOSS Caption lore overrides. Auto recognizes MOSS architecture but does not automatically opt into layout constraints.

## Author the scene, not the model syntax

The planner uses top-left-origin normalized XYXY edges, each from 0 to 1, with positive width and height. Do not supply raw model JSON or calculate pixels in the LLM.

```text
scene: Two adults on a rooftop.
right woman [persona] [box .52,.1,.95,.95]: holding a book
left man [character] [box .05,.1,.48,.95]: smiling
object box [.44,.68,.56,.84]: a red cup
text box [.1,.01,.9,.08]: {"caption":"White heading","text":"OPEN, \"TODAY\"\n第二行"}
environment: rooftop at dusk
```

Text item payloads are one-line JSON objects; escape quotes and line breaks inside `text`. Ownership markers and boxes are independent: subject identity and eligible scoped lore are resolved before layout serialization, and no internal markers reach the provider. Explicit boxes may overlap. Missing boxes can be inferred for unique left/center/right anchors; ambiguous or depth-only anchors remain descriptive prose. Malformed declared boxes fail with a useful error. Limit: 24 items. If there are no boxes, the compiler falls back to a caption. Object and text box captions do not accept scoped Lore markers; select subject/environment Lore in their existing fields.

## Native coordinate conversion

OpenMOSS uses absolute centered YXYX, not normalized XYXY. For canvas width W and height H, convert `[x1,y1,x2,y2]` to `[floor(y1*H)-H/2, floor(x1*W)-W/2, ceil(y2*H)-H/2, ceil(x2*W)-W/2]` (round floating-point edge products before floor/ceil). Studio performs this only after resolving recipe/aspect dimensions. Both dimensions must be explicit, aligned to 16 pixels and between 64 and 4096. The full document contains `summary`, `items`, `bbox_coord_space: "abs_centralized"`, and `bbox_format: "yxyx"`. Text items use `label: "text"` and the exact authored `text` string; object items use `label: "object"`.

Actual deterministic fixture outputs at 1280×960: [scene](examples/rooftop.layout.scene.txt), [native JSON](examples/rooftop.moss-layout.json), [Swarm BBox](examples/rooftop.moss-bbox.txt). These are generated by the backend contract, not diffusion outputs. The older [reference JSON](examples/moss-layout-reference.json) is a hand-authored schema illustration.

## Transport boundaries

Swarm's current MOSS bbox converter produces individual JSON object items, not the complete native layout document. In delegated mode Swarm owns final-dimension conversion; exact text is retained as prose guidance, **not** a dedicated text bounding box. Use Native JSON for positioned text items. A structured text field preserves the requested string, not a guarantee of pixel-perfect lettering.

Native JSON cannot be safely combined with `<preset:...>`, other angle-bracket prompt directives, prompt-mutating raw overrides, custom workflows or the Anima reference adapter. Studio rejects these combinations instead of trying to concatenate or edit a finished document. Use standard parameter-based LoRAs, clear prompt-mutating presets or select Swarm BBox. BBox permits native preset directives, but rejects custom/raw overrides that could replace the prompt. Harmless metadata/storage flags remain allowed. Ordinary model conditioning (LoRA, negative prompt, reference) is image-wide, not isolated by bounding boxes. Provider-side changes outside Studio's control are not proven safe by these checks.

## Inspect and verify

The inline inspector records resolved compiler, provider architecture evidence/fallback and transport, alongside the actual submitted prompt and Lore report. Original-setting retries retain the recorded compiler; current identity and recipe dependencies may still be re-read. For a live test use the three fixture modes with the same scene and a compatible checkpoint. Check the final provider prompt and dimensions before judging generated placement or lettering. No live GPU/Swarm verification is claimed by the deterministic tests.
