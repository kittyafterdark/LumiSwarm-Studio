# Member Atelier (1.1.0-alpha.7.3)

Open a hydrated Cast dialogue card's quick actions. The editor has a permanent template workspace and an SVG tool rail with a contextual drawer. The presentation gallery renders the actual template with the current member, dialogue and available background; category and text filters keep the gallery navigable. Selecting an entry previews it without closing the editor. The workspace is centered and fitted against the actual message container dimensions. On narrow/touch devices the tool rail and contextual drawer move below the preview, and desktop width is unavailable.

## Ownership and persistence

- Member tools: presentation, stage alignment, expression size and translation, crop framing, desktop card width. These apply to every rendered card for the same member ID in any chat with that Cast, including future cards. They are user-owned presentation preferences, not modifications to the portable Cast library. The backend stores one normalized difference per member in `cast-member-preferences.json` in user storage. Base member presentation, alignment and crop remain the fallback; default geometry is scale 1, zero translation and template width. The saved diff replaces the previous diff, and removed members are pruned on subsequent preference writes.
- This card: expression correction only. The authored expression is the default. Corrections remain scoped to the existing chat/message/packet/swipe identity in `cast-card-overrides-<chatId>.json`, with the existing 1,000-record bound. They do not mutate the source text or generate/upload any image. Restoring the original expression removes the correction (unless an older geometry record still needs to be preserved).
- Member and card drafts coexist. Apply saves the currently selected scope, stays in the editor, and preserves the other scope's draft. The footer indicates unsaved scopes; closing discards unsaved drafts. Revert member resets the member draft to base settings; apply to confirm. Restore original resets only the expression draft; apply to confirm. The folder shortcut opens the actual member in Cast for asset management.
- Legacy alpha.7.2 per-card geometry is not automatically promoted to a member preference. Untouched members retain their legacy geometry in chat until a member preference is saved or explicitly reverted. The new editor previews the member draft instead of promoting a legacy card's geometry. A saved empty member record acts as a migration marker: it means use the portable base and do not fall back to legacy card geometry. Existing legacy expression corrections remain valid. An expression-only save preserves legacy geometry only when no member preference exists; after adoption, new correction records contain only the expression and neutral geometry for compatibility.
- Member writes validate the active chat and member membership; user-scoped storage is serialized. Card correction writes validate the member and expression against the active Cast. Member changes signal the renderer to refresh; chat switches load the current member preferences alongside chat-scoped corrections. A failed or unconfirmed save does not claim success. Previously saved preferences are not exported with Cast albums.

## Canvas controls

Select an actor or the Size & position tool to reveal drag/resize handles. Scale is bounded to 75–150%, translations to ±20% horizontal and ±15% vertical. Crop has independent horizontal/vertical focus and 1–3× zoom; unsupported full portrait templates retain their natural framing. Desktop width remains 40–100% of the message container. Selecting the card opens width controls on desktop only. Artwork remains clipped to the card when adjusted; geometry values are bounded, not an automatic collision-avoidance solver for all fifty templates. Very tall content may scroll in the fitted workspace rather than shrink below a readable minimum. The editor is a view of the template, not a WYSIWYG editor for the dialogue or decorative template internals.

The Chromium fixture exercises real compiled rendering, thumbnails, canvas geometry, drag handles, scope isolation, expression correction, failed saves, template changes, remount, swipe identity, reset and theme integration. Six jsdom-dependent suites remain blocked in the offline build environment. Physical touch, live host integration, and exhaustive per-template transformation behavior require user testing. No generation or compiler behavior changed.

## Preference-load recovery (alpha.16.1)

A host chat switch updates the browser's active chat before the asynchronous persisted active-chat setting. A transient backend mismatch during `load_cast_card_overrides` now triggers up to three bounded read-only retries. Opening a valid Cast card while loading shows Member Atelier's loading state; permanent errors or missing replies offer Retry. The editor opens only after the saved preferences arrive and the original card identity is still current. Duplicate same-chat notifications do not close the editor. No write is automatically retried, and the original active-chat checks remain in place. Legacy quick picker behavior remains for unsupported identities. `npm run test:atelier:load` exercises the mocked race, manual recovery and stale response rejection in compiled Chromium. Live host verification is outstanding.
